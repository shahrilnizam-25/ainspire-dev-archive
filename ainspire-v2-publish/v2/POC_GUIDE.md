# AiNspire compact POC

Employee results first open a journey overview containing only the interactive Understand → Develop → Deploy → Measure journey and two equal-sized selector panels. No AI Profile or project detail appears until a panel or journey milestone is selected. Each section has Back to my journey. Understand your potential opens a centred persona feature matching the supplied visual, followed by numbered source reasoning statements below enlarged, high-contrast persona reference cards and one Your AI Contribution card combining contribution style and recommended role, linked to project matching. It retains the full AI Profile, with narrative, reasoning, confidence, contribution style, readiness dimensions, strengths, growth areas, personalised learning and video resources. Develop opens that profile and focuses the learning pathway. Find your contribution opens the suggested role definition and expected work, followed by project offers in a responsive grid; each offer also explains its project-specific contribution task. Measure shows accepted-project progress and benefits, with an empty-state guide before acceptance. The journey highlight follows the chosen view; it does not certify task completion. Learn, Practise and Demonstrate boxes and the Learning videos & resources subheading are removed. Learning recommendations appear directly under Recommended Learning Pathway. Every card has a direct YouTube watch link; recommendations without an attached video use the existing Microsoft beginner-series resource, labelled as a foundational supporting video, and a topic-specific search for deeper learning. Existing stored learning flags are retained for compatibility but Employee View no longer writes or presents them. HR and supervisor views are unchanged.

The assessment automatically suggests contribution roles and three learning actions. Persona and contribution style influence role direction, capability evidence influences support needs, and governed reflection keywords can prioritise responsible-AI learning. Reflection does not prove competence or change capability scores. Recommendations are suggestions, not verified skill eligibility. A supervisor checks domain experience, practical skills, availability and mentor support. Employee name is optional for the demo; otherwise the record ID identifies the participant.

## POC demonstration
1. Complete the assessment. Review profile, learning and project suggestions; no extra matching form is required.
2. Accept an offer. This expresses interest and creates a pending supervisor request.
3. Open /supervisor in the same browser. Select the employee row, open Approval & assignment, enter a demo supervisor name and decision reason, then Approve or Reject.
4. Approval does not assign the employee. Progress separately through Assigned, In progress and Completed.
5. HR /hr has exactly eight columns: Employee, AI Persona, Contribution Role, AI Project, Acceptance / Rejection, Supervisor Approval, Assignment, Benefit Status. One row per project response; participants without responses remain visible. Details expand inside the row.
6. In HR benefit details, record one project-owned cost avoidance, cost saving, productivity or internalisation benefit. Include baseline/result description, value and unit, period, evidence with quality check, and owner. Submit only after approved assignment completion. Record a named POC validator to validate; monetary benefits request a Finance validator.
7. Return to Employee View and Resume my POC journey to see updated status and benefits. No employee benefit-entry form is presented.

## Measurement
Cost avoidance prevents prospective expenditure. Cost saving reduces actual spending. Both use RM with a documented basis and Finance review. Productivity and internalisation use hours or outputs; they are not automatically converted to money. Internalisation can overlap with cost avoidance, so users must choose the benefit recorded and avoid duplication across rows. No aggregate financial total is presented. Benefit edits reset validation. Prior task-time records remain identifiable as legacy POC outcomes and are not automatically added to new benefits.

## Limits
Records and latest assessment use browser localStorage, up to 30 profile records, with same-origin update events. No authenticated supervisor/HR identities, real organisational routing, messaging, cross-device sync or external HR integration. The supervisor queue is explicitly a simulation. Optional names distinguish otherwise identical demo profiles. Existing records and original scores are retained; reviewed persona changes future recommendations, while accepted roles stay fixed. Only representative data and evidence references should be used. Current site audience is preserved.

YouTube cards retain curated/live source labels. Search links open YouTube with a learning-focused query; live retrieval needs the existing API key. Deterministic assessment works without TM Gateway credentials. Browser interaction and visual QA require the supported Sites browser capability; when unavailable the limits are reported alongside automated tests and build verification.
